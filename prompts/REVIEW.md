# 独立レビュー用の依頼

別セッションまたは独立したコンテキストのレビュー役へ渡す。最初は主担当の結論・推奨案・採否理由を添付せず、目的・制約・コード・観測事実を渡す。判明した事実を隠して再調査を強制する必要はない。

```text
あなたは今回の改善作業の独立レビュー役です。調査と提案だけを行い、ファイル・設定・データを変更しないでください。

対象: [対象プロジェクト]
依頼と制約: .harness/TASK.md、および既存の正規のAGENTS.md
確認済みの観測事実: [入力、ログ、測定値、再現手順、実験で確定した事実]
証拠: [関連コード・実行結果の参照先]
残り予算: [記入]

主担当の結論や推奨案を先に追認せず、まず一次の観測と制約から独立に考えてください。
そのため、最初の検討ではSTATE.mdやEXPERIMENTS.mdの結論・採否理由を読む必要はありません。
既存の規約、仕様、確認済みの事実を捨ててはいけません。

次を簡潔に返してください。
1. 現在の事実から確認できることと、まだ仮説であること。
2. 見落としていそうな有力案。最大3案とし、無理に数を埋めない。
3. 各案の最小検証、観測する結果、棄却条件、既存仕様への影響。
4. 今試す価値が最も高い1案と理由。根拠が不足するなら、先に必要な観測。

現在の案や過去の判断との照合は、上記の独立案を出した後で行います。
実装・採否・最終統合は主担当が担当します。
```

レビューを呼ぶ理由は、停滞・相互に矛盾する観測・重要な未検証仮定などに限定する。全工程に別の指揮役を増やす必要はない。
