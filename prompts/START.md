# 開始時にCodexへ渡す依頼

初回は対象プロジェクトでCodexを開き、以下を渡す。`<STARTER_PATH>` と今回の依頼を置き換える。準備から実装・検証まで一度に進める。`init` 実行済みなら、その結果を読んで続行する。`/goal` が使えない版では先頭の `/goal` を外す（自動継続は有効にならない）。

```text
/goal 次の依頼を案件の条件に具体化し、実装と検証まで完了してください。

今回の依頼:
[目的と期待する結果を書く]

スターターの場所: <STARTER_PATH>
対象: 現在のプロジェクト

既存の正規のAGENTS.md、関係する規約、今回の依頼を確認して作業を始めてください。
まず必要なら次を実行してください。
python "<STARTER_PATH>/tools/harness.py" init .

.harness/TASK.mdを今回の目的・完了条件・検証方法・変更範囲・予算に合わせて具体化してください。
完了条件は自動判定と手動判定を区別し、関連する仕様・評価データ・回帰ケースを固定してください。
曖昧な軽微事項は合理的に決めて記録し、結論や権限を左右する不明点だけを明示してください。

.harness/AGENTS.fragment.mdを既存の規約と照合し、必要最小限の統合案を短く示してください。
今回の作業手順として使える項目はそのまま適用し、既存のAGENTS.mdへ永続的に統合する変更は、この依頼または既存の許可に含まれる場合に限って行ってください。
許可が既にある変更について再承認を求める必要はありません。既存の指示を一括置換しないでください。

.harness/checks.jsonを読み、今回の判定に必要な既存コマンドを設定してください。
スターターのサンプルチェックが成功することを、このプロジェクトの合格とは扱わないでください。
用意した検証をbaselineとして実行し、初期状態と実際の出力先をSTATE.mdへ記録してください。
変更前から存在する失敗は、今回の変更による失敗と分けて記録してください。

続けて今回の依頼を実装・検証してください。確認済みのゴールや許可を繰り返し尋ねる必要はありません。
仮説→試したこと→証拠→採否→次をEXPERIMENTS.mdに短く残してください。
```
