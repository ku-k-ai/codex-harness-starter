# 設計意図

このスターターは、Codexが「作業する → 結果を確かめる → 次を決める」ための最小限の受け皿を用意する。モデルの思考手順を固定せず、目的、証拠、権限、再開情報を明確にする。

## 責務

| 構成 | 担当すること |
| --- | --- |
| `.harness/TASK.md` | 今回の目的、完了条件、固定する仕様・評価、許可範囲、予算 |
| `.harness/AGENTS.fragment.md` | 今回使う補助原則。自動では有効化しない |
| `.harness/checks.json` | 対象プロジェクトに必要な検証コマンドの設定 |
| `tools/harness.py` の `run` / `status` | 設定された検証の実行・結果確認 |
| `.harness/EXPERIMENTS.md` | 仮説と実際の結果、採否の短い履歴 |
| `.harness/STATE.md` | 現在地、確認済みの版、未達条件、次の一手 |
| `prompts/` | 開始、反復、独立レビュー、再開、仕上げの依頼文 |

`init <target>` は対象の `.harness/` に雛形を非上書きで配置する。既存の `AGENTS.md` を自動変更しない。共通指示と衝突するものは統合せず、既存規約に沿って必要な項目だけ使う。

## まず検証できる状態を作る

「改善を続ける」だけでは採否を決められない。STARTで依頼を具体化し、既存のテストや評価コマンドから今回必要なものを設定する。変更前のbaselineと変更後のcandidateを同条件で比較する。

終了コードが成功しても、それで証明できる範囲は設定したチェックだけである。画面の使いやすさやドメイン上の妥当性など、手動要件があるならTASKに残す。検証コマンドや正解データを変更して数値だけを良くしない。

記録には、仮説 → 試したこと → 証拠 → 採否 → 次を残す。コードの版だけでなく、評価データ・モデル/実行設定・外部環境が変わった場合も分かるようにする。環境が変わった結果は同じ条件の改善とは扱わない。

## 継続と終了

反復が必要ならCodexのGoalsを使う。利用できないクライアントでは同じRUN本文を通常の依頼に使い、RESUMEで引き継げる。公式仕様へのリンクは[SOURCES.md](SOURCES.md)を参照。

このスターター自身はモデルAPIを呼ばず、セッションを自動起動しない。TASKの時間・試行・API費用上限は作業指示であり、全作業を外から強制停止する仕組みではない。検証コマンドのタイムアウトがある場合も、Codex全体やAPI利用額の上限とは区別する。

終了時は全要件達成を `done`、実行可能な経路がない外的な障害を `blocked`、設定した上限到達を `budget` として記録する。自動チェックに合格していても必須の人の確認が残る場合は `done` にしない。途中で必要な確認を省略して達成扱いにすることも、完成後に無関係な変更を続けることも避ける。

## 停滞時にだけ見方を変える

時計だけで停滞を判定しない。長い試験や再現条件の確定も進捗になりうる。同じ仮説で新しい証拠や改善が得られない、という案件に合ったトリガーをTASKに置く。

レビュー役には目的、制約、一次の観測を渡す。初めは主担当の結論を伏せ、独立の案を出してから比較する。確認済みの事実を捨てない。主担当は結果の採否と統合を持ち、レビュー役は読取と提案に限定する。同じモデルを別コンテキストで使っても、誤りが完全に独立になるとは仮定しない。

## 会社と自宅への適用

汎用の手順は共有し、接続先、資格情報、業務データ、社内規約は各環境で管理する。Windowsネイティブ、WSL、利用するCodexクライアントは既存環境に合わせる。Bash、tmux、特定のクラウドへの移行を前提にしない。

特許分類なら、既知の誤りだけへの最適化を避け、重大な誤除外、既知回帰、未見の評価データを分ける。検索式なら、実行可能性、既知の重要文献の回収、レビュー対象件数を別に見る。既知正例の回収率を真の再現率と呼ばない。いずれも業務上固定された分類規則や担当範囲を勝手に変更しない。

## 足す前に比べる

同じ開始点・データ・モデル/設定・予算で、現在の運用とこの薄い構成を比較する。初期選別は小さな実案件数件でよい。完了率、人の介入、回帰、時間、費用を見る。初期の数回だけで統計的な優越を主張しない。

途中停止や停滞が実際に残る場合、その失敗に対応する部品を1つ追加して測る。指摘のたびにAGENTSを増やさず、再現する観点だけを残す。モデル更新後も、権限と業務制約を保持して補助的な指示の有無を比べる。

## 今回は入れないもの

無条件のStopフック、大量の指揮役、競技スコア専用の最適停止計算、全操作への追加承認、記事中の指示による正規AGENTSの無視は含めない。必要性が確認できた機構だけを後から追加する。
